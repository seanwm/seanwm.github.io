Brownie Badge: Coding Basics

Today we're going to learn about computer programming! We'll learn what a program is, and some of the ways that people give instructions to computers. We'll also learn a little about how computer programming started, and about some of the women in computer science at its very beginnings and today.

Coding Vocabulary

Algorithm

This word still sounds, to me, like it should be something very complicated! But it’s just a list of instructions to complete a certain task or solve a problem. Think of things that you usually do the same way each time: getting ready for bed (say goodnight, brush teeth), going to the grocery store (walking/driving directions), making a little drawing you like to do. You follow an algorithm to make a paper fortune teller, and follow a different algorithm to use one. Opal has a few different algorithms for drawing cats. I have a different algorithm for cracking eggs than my Mom does.

Programmers try to find the best way to do something for specific situations. How exact do we need to be? How fast does it need to be? How many times do we have to do it? This can be a fun puzzle to solve, and is one kind of thing that programmers debate with each other.

Event
An event is when a program has to react to something outside of the program. Often this is a person doing something, like pressing a key, moving the mouse, or tapping on a screen. But lots of other things can be events, too: a different program finishing a task, the clock reaching a certain time, or a loud sound happening. Programs are setup so that when one of these events happens, an algorithm—a part of the program—runs. At school, when the fire alarm goes off (an event), students stop what they’re doing and follow their teacher outside (an algorithm).
Loop
Loops—doing the same steps over and over again—are everywhere in computer programs. A loop might be how a program waits for an event: by checking, over and over again, “is someone pushing the space bar?” To animate moving a picture across the screen, a program might have a loop where the picture is moved a tiny bit every fraction of a second. You could make your own timer program by having a loop that adds 1 to the total number of seconds, over and over. Sometimes a loop can do the same steps each time, but to a new “thing” each time. When your class does show-and-tell, the same thing happens over and over—someone comes to the front, talks about something, and answers a few questions—but each time it happens with a different kid.
Variable
A variable is a container for something. It could be a number, a word, a sentence, a picture, a list of things, a button on the screen—all kinds of things. A program can put things into this container, and it can use whatever is in the container. In the timer program, the “total number of seconds” would be a variable. To have a computer say hello to someone, you could write a simple program that stores and then uses a variable:
  • Step 1: “What is your name?”
  • Step 2: Someone types in, “Sean”.
  • Step 3: The program puts “Sean” in a variable called “name”.
  • Step 4: The program tells the computer to say, “Hello [name], nice to meet you!” Because the “name” variable has “Sean” in it, the computer says, “Hello Sean, nice to meet you!”
